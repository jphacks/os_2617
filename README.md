# Meal maneger

[![IMAGE ALT TEXT HERE](https://jphacks.com/wp-content/uploads/2026/07/IMG_5316.png)](https://www.youtube.com/watch?v=piaNsc6ilBI)

## 製品概要
### 背景(製品開発のきっかけ、課題等）
グループで食事に行くとき、「どこでもいいよ」「なんでもいい」と言い合ってなかなかお店が決まらない、という経験は誰にでもあります。
LINE で一人ひとりに好みを聞いて回ったり、幹事が一人で悩んだりするのは手間がかかり、結局あまり納得感のないお店になってしまうこともあります。
そこで、「幹事の負担を減らし、全員の好みを反映した形でお店を決められるようにしたい」という思いから、このアプリを作りました。

### 製品説明（具体的な製品の説明）
**Meal maneger**は、グループの食事のお店を「アンケート」で決める Web アプリです。

1. **ホスト（幹事）が条件を決めてルームを作成**：場所・人数・日時・予算・ジャンル（居酒屋／カフェ／ご飯）・飲み放題・席の希望・テイクアウト
2. **共有リンクを LINE などで送る**：参加者はアカウント登録不要。ニックネームを入れるだけ
3. **参加者がジャンルの好みを ◎〇× で回答（約30秒）**：たとえば居酒屋なら「大衆居酒屋・焼き鳥・海鮮・バル・バー」をそれぞれ評価
4. **全員が回答する、またはホストが締め切る**：おすすめのお店 TOP5 を、点数と内訳つきで表示
### 特長
#### 1. 特長1
**参加者は選ぶだけ**
参加者が答えるのは、ジャンルの小カテゴリごとの ◎（行きたい）〇（どちらでも）×（避けたい）だけ。初期値は全部〇なので、変えたいものだけ選び直せば完了します。ログインやアプリのインストールも不要です。

#### 2. 特長2
**「幹事が決める条件」と「みんなの好み」を分けて採点**
場所・予算・日時・人数・飲み放題・席・テイクアウトといった**条件**は幹事が一度だけ決め、参加者には**好み**だけを聞きます。参加者の負担を減らしつつ、条件を満たさないお店は足切り・減点され、好みはグループ全体の合計ポイントで反映されます。

#### 3. 特長3
**結果の理由がわかる（スコアの内訳つき）**
各お店に 100 点満点のスコアを表示し、「スコアの内訳を見る」から項目ごとの重み・評価・得点を確認できます。「予算内」「飲み放題あり」「×が1人」などのおすすめポイント・注意点もタグで表示されるので、「なぜこのお店なのか」をグループで納得して決められます。

### 解決出来ること
* 幹事が一人で悩む・全員に個別で好みを聞いて回る手間をなくす
* 「どこでもいい」で決まらない状況を、◎〇× という軽い回答で数値化して解消する
* 苦手なジャンル（×）を事前に拾い、誰かが我慢するお店選びを減らす
* 飲み放題必須・個室希望などの条件を満たすお店を自動で絞り込む
 
### 今後の展望
* ぐるなび・ホットペッパーなどの外部 API と連携し、実在のお店のデータでランキングを出す
* 対応エリアの拡大（現在は大阪・京都の 9 エリア）
* 日程調整機能との連携（回答時に参加可能な日時も聞く）
* アレルギーや苦手な食材など、個別の制約の入力
* 結果画面から店舗の地図・予約ページへの導線を追加

### 注力したこと（こだわり等）
* 参加者の回答の手間を最小限に（初期値〇・ログイン不要・ニックネームのみ）
* ランキングの透明性：重み付き平均のスコアを項目ごとに分解して表示
* 予算スコアの非対称な設計：予算を超えると不満につながりやすいため、安い側には緩やかに、高い側には厳しく減点
* 条件に応じて採点項目を切り替える設計（「飲み放題どちらでも」「席どこでも」などは採点に含めず、Must 条件だけペナルティを掛ける）
* モバイルファースト・ダークモード対応の UI（LINE で共有されて開く場面を想定）
* ホスト用 URL のトークンによる締め切り権限の管理、レート制限・CSP などの基本的なセキュリティ対策

## 開発技術
### 活用した技術
#### API・データ
* モックの店舗データ（大阪・京都の 9 エリア・99 件、店名・データはすべて架空）
  * 将来的にぐるなび API / ホットペッパーグルメ API 等へ差し替え可能な形（`fetchRestaurants()`）で実装


#### フレームワーク・ライブラリ・モジュール
* Node.js 22 / Express 4（API サーバー・画面配信）
* node-postgres（`pg`）（PostgreSQL への保存）
* フロントエンドはフレームワークなしの素の HTML / CSS / JavaScript（1 ページのアプリ、History API でルーティング）

#### デバイス
* スマートフォン・PC のブラウザ（レスポンシブ対応）
* インフラ：Render（Web サービス）、Neon（PostgreSQL）

### 独自技術
#### ハッカソンで開発した独自機能・技術
* **グループの好みを反映するランキングアルゴリズム**
  * 参加者の ◎(+1) 〇(0) ×(−2) を小カテゴリごとに集計し、1 人あたりの平均を 0〜1 に換算
  * 場所（距離の指数減衰）・予算・小カテゴリ・飲み放題・席・テイクアウト・店の評価を、重み付き平均で 100 点満点に統合
  * Must 条件（飲み放題必須・テイクアウト希望）を満たさない店には ×0.6 のペナルティ
  * 足切り条件：ジャンル違い・エリア外（5km 超）・定休日・営業時間外（深夜営業の判定を含む）・人数オーバー
  * 実装：[src/ranking.js](src/ranking.js)
* **ホスト用トークンによる締め切り制御と自動締め切り**（全員回答で自動クローズ、同名の再回答は上書き）
  * 実装：[server.js](server.js)
* **保存先の切り替え**：`DATABASE_URL` があれば PostgreSQL（Neon）、なければメモリ保存。ルーム・回答は JSONB で保存し、項目追加時のテーブル変更が不要
  * 実装：[src/store.js](src/store.js)
* **ポーリングによる回答状況・結果のリアルタイム更新**（フロントエンド）
  * 実装：[public/app.js](public/app.js)
